# The Video step clears the GPU, asking first

InfiniteTalk needs about 10 GB of the 12 GB card, and other programs on this machine can take most of it. The shared llama.cpp server (`llama-server@11434`; `llama-bridge` wants it, so stopping the server leaves the bridge running) can load an 8–9 GB model at any moment, and only checking free VRAM failed here. So before a Video, CloneCraft lists every program holding 100 MiB or more of GPU memory. For each one it asks the Operator whether to stop it, and, for a systemd service, whether to start it again afterwards. Services are stopped and started with sudo. Other programs can only be stopped, because restarting them would need their original environment. CloneCraft saves the answers in a git-ignored local settings file and only asks about programs it hasn't seen before. When the Video step ends, whether it succeeds, fails or is interrupted, CloneCraft starts again everything the Operator asked it to restart. The Voiceover step (about 8.5 GB) uses the same list-and-ask flow, but only when less than that is free; with enough free memory it asks nothing and stops nothing.
